# 真实思源笔记内容核查范围

## 1. 核查对象

本仓库中的 `.sy` 文件是用户从实际思源笔记库导出的真实笔记数据，不是为了测试而新建的样例笔记。核查必须以仓库中的这批导出笔记为对象，不得把它们描述成测试数据，也不得要求用户重新创建一套笔记来证明真实性。

当前仓库基线（以每次重新扫描生成的 `catalog/generated/catalog.md` 为准）：

- 2,667 篇 `.sy` 文档，来自 7 个顶层笔记本/目录。
- 当前扫描均为 `PARSED`，表示 JSON 结构可解析，不代表正文提取无损或内容正确。
- 5,309 条附件引用；`assets/` 未纳入 Git，因此云端无法检查附件实体及图像/文件内容。
- 4,783 条文档—主题命中记录；主题是全文关键词规则的初筛结果，不是语义审核。
- 22 条标题风险信号；是待检查线索，不是已确认错误。

## 2. 核查目标与边界

项目的首要目标是让真实笔记可完整、准确地被读取、组织、检索和复用，并逐步识别内容问题。

### A. 导出数据与解析完整性（可自动化，优先完成）

逐篇检查：

1. `.sy` JSON 是否可解析；根节点、Properties、Children 及块节点结构是否符合预期。
2. 正文提取是否覆盖实际可见文本；识别当前提取器未处理、被跳过或错误合并的节点类型。
3. 标题是否正确读取 Properties.title；回退到正文首行/文件名的情况必须单独标识。
4. 父子文档关系、容器文档、空正文文档是否被正确识别。
5. 块 ID、引用、嵌入、资源引用等关系是否可提取；暂不支持的关系必须显式报告，不能静默丢弃。
6. 原始文件数量、解析数量、索引数量及哈希基线是否一致；不得仅用“JSON 全部解析成功”推导内容无损。

### B. 内容组织与检索质量（自动初筛 + 定向复核）

以真实笔记正文为依据，检查：

1. 标题与正文是否明显错位、标题是否只是编号/占位词/正文句子。
2. 主题标签是否由孤立提及、宽泛词、目录文字或引用片段误触发；是否存在正文主题明显遗漏。
3. 同一内容的完全重复、近似重复、不同版本/修订稿及重复章节。
4. 正文为空、异常短、异常长、乱码、编码替换字符、HTML/Kramdown 残留、重复段落和异常截断。
5. 多主题长笔记是否需要章节级索引，而不是只给整篇笔记打标签。
6. 关键实体与术语是否可检索，例如经方/方剂名、中药名、穴位、经络、证候、病名、剂量和出处。

自动检测结果必须保留原文定位和触发原因。算法只能产生候选问题，不能擅自改写原始笔记或把疑似问题直接判为错误。

### C. 中医知识内容核查（必须有依据，分层推进）

这是内容层面的实质核查，不等同于目录或书目元数据核查。

- 对方剂、药物、剂量、配伍、证候、治法、经穴、经典原文等内容，先抽取可定位的知识主张。
- 每条主张保留原笔记路径、标题、块/段落定位和原文摘录。
- 与明确指定的可靠底本、教材、经典版本或权威资料对照；记录一致、差异、冲突、缺少依据等状态。
- 不同医家、流派、版本之间存在差异时，记录来源和语境，不强行合并成唯一结论。
- 对无法确认的主张保留待核验状态，不由模型补全出处，不把网络搜索摘要当作原始证据。
- 自动提取和模型辅助只用于定位、归纳和比对；涉及医学事实的最终结论必须能回溯到明确材料。

本项目是资料整理与学习辅助，不把笔记核查结果包装成临床诊断、处方或疗效验证。

## 3. 现有工作的正确定位

| 现有产物 | 实际证明了什么 | 不能证明什么 |
|---|---|---|
| `documents.csv` | 已扫描文档的元数据、路径、解析状态、有限正文检索片段 | 正文提取无损、知识正确 |
| `topic_index.csv` | 关键词命中的导航索引 | 主题语义准确 |
| `topic_rule_audit.csv` | 逐文档—主题的关键词触发记录 | 标签是错误或正确 |
| `title_extraction_audit.csv` | 标题回退及静态风险线索 | 标题一定错误 |
| `document_hierarchy.csv` | 从导出目录关系推导的父子层级 | 思源全部块级引用和语义关系 |
| `asset_references.csv` | 笔记中发现的附件路径引用 | 附件文件存在、内容匹配或清晰可读 |
| 来源候选/版本/校勘队列 | 笔记中出现的来源线索及其待核实项 | 笔记正文的知识内容已经核查 |

来源身份、版本和文本校勘属于知识主张核查的证据支撑工作，不应凌驾于真实笔记的解析完整性、内容组织和检索质量之上，也不应把所有来源候选都当成必须先由用户逐条完成的前置任务。

## 4. 下一阶段实施顺序

1. **解析覆盖审计**：按 SiYuan 块类型统计正文提取覆盖情况；建立节点类型—提取策略矩阵；对未处理节点、空文本节点和特殊内容生成定位清单。
2. **内容异常审计**：对全部 2,667 篇扫描乱码、异常空白/长度、重复段落、截断迹象、标题正文错位、结构异常，并输出可定位报告。
3. **检索质量审计**：检查现有主题规则的漏检/误检候选，增加中医术语实体索引和章节级定位；保留原始触发词与上下文。
4. **知识主张抽取**：从真实笔记中分领域抽取方剂、药物、剂量、证候、治法、经典原文等主张，形成可追溯的核查队列。
5. **依据对照**：按主张类型和明确底本分批核查，记录差异及来源定位；冲突不自动消解。
6. **回归与防损**：新增测试保证解析器不会静默丢弃已识别块类型；每次改动都重新扫描整个仓库，比较文档数、文本提取统计、节点类型分布和审计结果。

## 5. 验收规则

- CI PASS 只代表代码测试、全量扫描和数据结构校验通过。
- 全部 `.sy` 可解析，不等于全部正文提取完整。
- 关键词命中不等于语义正确；无命中不等于没有相关内容。
- 文件哈希不等于内容正确；文件名/路径不等于附件匹配。
- 书目来源 VERIFIED 不等于该笔记中的每条医学主张 VERIFIED。
- 不得为追求“全部完成”而把未核验项改成通过；所有问题必须保留原文定位、检测方法和状态。
- 任何自动修复都必须保留原始数据，不得覆盖用户导出的原始 `.sy` 文件。

后续开发和报告以本文件的范围与顺序为准。若旧的人工复核说明与本文件冲突，以本文件的内容核查优先级为准；旧队列可作为辅助证据工作流继续保留，但不能代替内容审计。
